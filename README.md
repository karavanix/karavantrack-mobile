# YoolLive driver app

Flutter app for drivers: accept loads, move them through their statuses,
share location while a load is active.

## Running

Without flags the app talks to production (`api.yool.live`, `app.yool.live`).
To point it elsewhere:

```sh
cp env/dev.example.json env/dev.json   # edit the URLs
flutter run --dart-define-from-file=env/dev.json
```

## Layout

The structure follows Flutter's
[app architecture guide](https://docs.flutter.dev/app-architecture) (the
Compass sample):

- `lib/config/` — build-time settings (`env.dart`) and the provider graph
  (`dependencies.dart`).
- `lib/data/services/` — stateless access to the outside world: the API
  (dio; `AuthInterceptor` refreshes the token on 401), device storage.
- `lib/data/repositories/` — the source of truth for each kind of data;
  `AuthRepository` is the only owner of the tokens.
- `lib/routing/` — go_router; `redirect.dart` decides which entry screen the
  user must see and is covered by a table test.
- `lib/ui/` — `core/` (theme, translations, shared widgets) and one folder
  per feature with `views/` and `view_models/`.
- `lib/utils/` — `Result`, `Command`, the log.

Translations live in `lib/ui/core/l10n/app_{en,ru,uz}.arb`; the Dart code is
generated by `flutter pub get` / `flutter gen-l10n`.

UI code imports `package:material_ui`, not the framework's frozen
`package:flutter/material.dart`.

## Tests

```sh
flutter test
```

Tests use fakes (`test/testing/`), not mocks: `FakeServer` replaces the
network under dio, `FakeLocalStore` the device storage.
